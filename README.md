Flash使用步骤：显式电气对准并禁能 → 在控制台保存 → 等待最终成功事件 → 复位后检查READY、已从Flash恢复且输出关闭。每次仍采集电流零偏；仅无有效记录时需要重新电气对准。换电机、相线或磁铁/编码器安装前先废弃记录或提升 `APP_ELECTRICAL_CAL_CONFIG_REV`。校准页受控读取发生双位ECC时保持禁能、报告0232=12且不恢复旧值；人工重新对准并保存成功后才解除ARM限制。程序区、系统区、时钟或无法归因的NMI仍硬禁能死循环。真实ECC/写入中掉电尚未验收。

CAN软件复位：先读GET_INFO selector5校验值，再发op=0x1D、index=0xA55A、argument=该值；能力位8表示支持。仅在输出/驱动器关闭且无校准或待ARM时接受，等确认帧实际发送完成后由主循环复位。重启保持禁能，不自动对准或恢复运行。当前并行控制台收到确认后保留适配器连接，重新读取被复位节点，其他电机独立运行。详见[本轮验收与复位协议](docs/can-stage4-closeout-2026-10-17.md)。真实关节安装/限位/带载/制动及速度精度优化继续暂缓。

控制台多电机并行版：同级`CAN-Console`连接一次即可发现多个不同ID的节点；“多电机控制”页可批量配置模式/限流、启动所选、分别编辑目标后一起应用、禁能所选。双击只切换当前查看节点，不停止其他电机；每节点维护独立会话与5 ms目标周期，批量启动失败停止本批次，共享串口错误撤销全部控制。无需改CubeMX或重烧固件。已有99项离线回归通过；2026-10-17三台实物23项检查通过，覆盖独立Iq目标、单台停止/目标租约超时隔离、单板复位与广播停止，最大连续主机排队间隔约8.56 ms。末态全部禁能、无故障、TEC/REC=0/0、COM16释放；RAM限流100 mA、速度上限5 rad/s，节点3因本轮复位需重新电气对准。详见[三电机实测记录](docs/can-three-motor-test-2026-10-17.md)，操作说明见同级控制台README。

## 项目简介

**FOC_v1** 是一个基于 STM32G431CBT6 微控制器的嵌入式无刷直流电机磁场定向控制 (FOC) 项目。功率级为 **DRV8323H 三相智能栅极驱动器 + 6 颗外置 N-MOSFET**，使用 14 位 AS5047P 磁旋转编码器进行位置反馈，**INA240A2 电流采样放大器 + 10 mΩ 分流电阻** 进行相电流采样，硬件 CORDIC 加速三角函数计算，实现完整的三环级联 FOC 控制（位置环 → 速度环 → 电流环），同时通过 USART2 DMA 与上位机 VOFA+ 进行实时数据交互与在线调参。

### 主要特性

- **主控**: STM32G431CBT6 (ARM Cortex-M4, 170 MHz, FPU, 硬件 CORDIC)
- **功率级**: DRV8323H 栅极驱动器 (3x PWM 模式) + 6× 外置 N-MOSFET，内置电荷泵支持 100% 占空比
- **相电流采样**: 双 INA240A2 (50 V/V) + 10 mΩ 分流，双 ADC 同步注入采样 + 16× 硬件过采样，自动零点校准 (2000 样本)
- **母线监测**: INA219 经 I2C1 读取母线电压/电流，5 Hz 更新；有效实测值参与 FOC 调制比换算，异常或过旧时禁能
- **位置传感器**: AS5047P 14 位磁旋转编码器 (SPI1 + DMA，非阻塞流水线读取，多圈累积)
- **控制算法**:
  - Clarke + Park 变换，SVPWM 空间矢量调制
  - 三环级联控制：位置环 (1 kHz P 控制) → 速度环 (1 kHz PI 控制) → 电流环 (20 kHz Iq/Id PI)
  - Iq/Id 双轴 PI 闭环控制（Tustin 离散化 + 双向抗饱和 + dq 矢量抗饱和回灌）
  - 交叉解耦 + 反电动势前馈补偿 (>1000 rad/s 时自动启用)
  - CORDIC 硬件加速 sin/cos 计算，一个 PWM 周期的流水线角度补偿
- **传感器对准**: 自动零电角度校准流程（静态电压矢量锁定 + 平均采样）
- **编码器失效保护**: 两级判定 — 瞬时陈旧则冻结角度并折减电流限幅，连续 20 帧 (1 ms) 则锁存停机
- **安全停机**: `foc_safe_stop()` 统一关断入口，可在任意上下文调用（清 CCR → 关 MOE → 关驱动器使能 → 清 PID 积分器）
- **上位机通信**: VOFA+ 遥测14通道@100 Hz（**460800 bps**）；文本命令实现保留，当前CAN控制模式不开放UART运动/调参

串口总开关位于 `Core/Inc/app_config.h`：`APP_UART_ENABLE=1` 开启 UART2 接收、遥测和日志；`=0` 编译跳过 UART2 初始化，并由用户钩子关闭其 DMA 中断。默认关闭（APP_UART_ENABLE=0），修改后需重新编译。当前为CAN第三阶段速度/位置台架软件（软件已接入、第三阶段实物测试未通过）：上电保留自动偏置校准和电气对准，完成后关闭输出；CAN会话/ARM/Iq已实现，默认按用户请求设置初始Iq限值1.5 A、指令上限2.5 A、软/硬过流阈值2.8/3.0 A（profile=1），仍需有效会话和健康检查。该设置尚未实测验证，不代表电机或整板额定能力。UART只监视，关闭CAN也不会自动恢复闭环启动。CubeMX重新生成后应核对用户钩子并重新验证两种配置。

`APP_COMMAND_TIMEOUT_MS`默认`0`，表示人工值守台架保持最后目标。远程控制集成时应配置有限超时，并周期发送有效运动命令或`HB=1\n`保活；无效帧和单纯调参不续期。超时锁存停机，需要复位。保护阈值尚待电机额定与实测核定，软件配置和验证结果见[修复记录](docs/fix-results-2026-10-09.md)。

关节机械零点与 FOC 电气零点不同：轮子无需机械回零，但所有电机仍需有效的电气零点及电流采样偏置。当前 `foc_alignSensor()` 实现电气对准；关节机械零点设置属于 CAN 改造方案，尚未实现。
- **环路频率**: PWM 40 kHz、电流环 20 kHz，速度环 1 kHz，位置环 1 kHz，遥测 10 ms 周期
- **编码器接口**: 双缓冲缓存 (TIM2 ISR 写入, FOC 电流环读取)，约4 ms滑动窗口速度估算

## 硬件架构

当前默认母线为12 V。INA219在现有网表中直接接母线，器件输入额定及母线瞬态会约束整板范围；驱动器自身支持的电压范围不等于整板额定。整板最高安全电压尚未核定，不能按原图中的6–60 V接入电源。

```
        VBAT (当前软件默认 12V，整板额定待核定)
            │
      ┌─────┴──────────────────────────────┐
      │        DRV8323H (U9, QFN-40)       │
      │  MODE = 47kΩ→AGND  ⇒  3x PWM 模式  │
      │  ENABLE ← PB10 (DRV_EN, 高有效)     │
      │  INH1/2/3 ← PA9/PA10/PA8 (PWM)     │
      │  INL1/2/3 ← PB13/14/15 (静态高)    │
      │  nFAULT → PB9 (10kΩ 外部上拉)      │
      └───┬────────┬────────┬──────────────┘
        GH_A     GH_B     GH_C   (经 2.2Ω)
        GL_A     GL_B     GL_C   (经 2.2Ω)
          │        │        │
      ┌───┴──┐ ┌───┴──┐ ┌───┴──┐
      │Q1 Q2 │ │Q3 Q4 │ │Q5 Q6 │   三相半桥
      └───┬──┘ └───┬──┘ └───┬──┘
          │        │        │
          └────────┼────────┘
                   │
   MOTOR_A ──── R4 (10mΩ) ──── MOTOR_A_CS ─┐
   MOTOR_B ──── R23 (10mΩ) ────────────────┼──→ U4/U5 (INA240A2, 50V/V)
   MOTOR_C ──── R5 (10mΩ) ──── MOTOR_C_CS ─┘        │
                                                    │ SENSOR_A → PA0 (ADC1_IN1)
                                                    │ SENSOR_C → PA1 (ADC2_IN2)
```

> **3x PWM 模式说明**: `MODE` 引脚经 47 kΩ 接 AGND，DRV8323H 进入 3x PWM 模式，由器件内部根据 `INHx` 生成互补高低边驱动并插入死区。`INLx` 在此模式下不参与逻辑，但**必须保持确定电平以避免输入级悬空误触发**，故 PB13/PB14/PB15 上电即置高并全程保持。
>
> **B 相电流**由基尔霍夫定律推导 (`I_B = -(I_A + I_C)`)，不做独立采样。

### 时钟与电源

| 项目 | 配置 |
|------|------|
| HSE | **8 MHz 有源振荡器**（4 脚 OSC1）→ `RCC_HSE_BYPASS` |
| PLL | M=2, N=85, R=2 → **SYSCLK 170 MHz** |
| Flash 等待周期 | 4 WS |
| 稳压器 | `PWR_REGULATOR_VOLTAGE_SCALE1_BOOST` |
| ADC 时钟 | SYSCLK / 4 = 42.5 MHz |

> 使用有源振荡器而非晶振，频率精度优于 ±50 ppm，是 460800 bps 可靠通信的物理基础（波特率寄存器误差仅 −0.0038%）。

## 快速开始

### VOFA+ 上位机连接

连接 USART2 (PB3 TX, PB4 RX)，波特率 **460800**：

- **遥测接收**: 打开 VOFA+，添加 14 通道数据显示
- **命令发送**: 在 VOFA+ 终端输入文本命令，格式为逗号分隔的键值对；发送设置勾选“追加换行”，推荐 LF 或 CRLF，也支持单独 CR。未带结束符的内容会等待后续字节，不会执行。

> ⚠️ **波特率必须设为 460800**。115200 下 14 通道遥测帧的带宽需求 (17.8 kB/s) 超过链路能力 (11.52 kB/s)，会导致发送队列持续积压。

支持的遥测通道 (14 通道, 100 Hz)：

通道    | 变量              | 说明
--------|-------------------|------------------
[0]     | id_target         | D 轴目标电流 (A)
[1]     | id_meas           | D 轴实测电流 (A)
[2]     | iq_target         | Q 轴目标电流 / 转矩指令 (A)
[3]     | iq_meas           | Q 轴实测电流 (A)
[4]     | velocity_raw      | 滑动窗口原始速度 (rad/s)
[5]     | velocity_filt     | 速度环滤波后角速度 (rad/s)
[6]     | speed_setpoint    | 速度目标值 (rad/s)
[7]     | speed_kp_active   | 速度环当前生效的 P 增益（增益调度）
[8]     | status_flag       | 命令同步标志 (收到命令置 1，发送后清零)
[9]     | mode              | 控制模式 (0=转矩, 1=速度, 2=位置)
[10]    | position_target   | 位置目标值 (多圈 rad)
[11]    | position_meas     | 实测多圈位置 (rad)
[12]    | bus_voltage       | INA219 母线电压 (V)
[13]    | bus_current       | INA219 母线电流 (A)

支持的命令：

命令  | 说明                              | 示例
------|-----------------------------------|--------
T=V   | 转矩 / Iq 电流指令 (A)            | `T=0.5`
D=V   | D 轴电流目标 (A)                  | `D=0.0`
P=V   | Q 轴电流环 P 增益                 | `P=10.485`
I=V   | Q 轴电流环 I 增益                 | `I=371.25`
DP=V  | D 轴电流环 P 增益                 | `DP=10.485`
DI=V  | D 轴电流环 I 增益                 | `DI=371.25`
S=V   | 速度目标值 (rad/s)                | `S=50`
SP=V  | 速度环 P 增益（会同时关闭增益调度） | `SP=0.09`
SI=V  | 速度环 I 增益                     | `SI=0.1`
SG=V  | 增益调度开关 (0=手动 SP, 1=调度)  | `SG=1`
SPL=V | 调度低速区 P 增益                 | `SPL=0.09`
SPH=V | 调度高速区 P 增益                 | `SPH=0.02`
PS=V  | 位置目标值 (多圈 rad)             | `PS=6.28`
PR=V  | 相对位置增量 (rad，以实测位置为基准，限幅 ±2π) | `PR=1.57`
PP=V  | 位置环 P 增益 (rad/s per rad)     | `PP=10`
PL=V  | 位置环速度限幅 (rad/s，`PSL` 的别名) | `PL=100`
PSL=V | 位置环速度限幅 (rad/s)            | `PSL=100`
PAL=V | 位置轨迹加减速度限幅 (rad/s²)     | `PAL=40`
CVL=V | 电流环 dq 电压矢量限幅 (V)        | `CVL=6`
SIL=V | 速度环 Iq 电流限幅 (A)            | `SIL=0.6`
M=V   | 控制模式 (0=转矩, 1=速度, 2=位置) | `M=1`
HB=1  | 外部控制保活（启用超时配置时续期） | `HB=1`

示例: `M=2,PS=6.28,PP=10,PSL=100` — 切换到位置模式，目标 1 圈，P=10，限速 100 rad/s

> **命令语义**: 必须以 LF（`0A`）、CRLF（`0D 0A`）或 CR（`0D`）结束；一帧先完整校验再在临界区内提交，`M=1,S=4`与`S=4,M=1`等价。未知键、畸形数值、非有限值、越界值或未就绪/故障状态拒绝整帧，不执行前缀。只有接受的命令置`status_flag=1`。同模式标签不重置动态状态。`T/D`共用dq矢量限值，`SIL`不能超过当前候选硬上限2.5 A。

连接排查可在闭环遥测开始后发送 `HB=1` 并追加 LF：该指令不改变运动目标，接受后遥测通道[8]会有一帧为1。不带结束符时既不会执行，也不会出现`[CMD] rejected`；若出现拒绝日志，检查命令格式、数值范围及启动/故障状态。脚本应发送实际控制字符，例如 Python 的 `port.write(b"HB=1\n")`。

## 安全机制

### 安全启动顺序

1. **上电保持关断**: `DRV_EN` (PB10) 上电为低；先进行编码器诊断，最多10轮重试，连续两组有效诊断/幅值才通过。失败时保留关断，不启动PWM、ADC或电流校准
2. **电流零点校准**: 驱动器关断状态下采集2000个有效样本，检查偏置、峰峰值、方差及量程余量；200 ms内未完成则锁存故障
3. **驱动器使能**: 校准、母线和编码器诊断通过后，取得新鲜角度再置高`DRV_EN`；等待nFAULT连续5 ms为高，总等待上限50 ms
4. **传感器对准**: `foc_alignSensor()` 从零渐升静态电压矢量 (0 → 3 V, 100 ms)，保持 300 ms，降回 1 V 后采样零电角度，再平滑撤除电压
5. **校准后禁能**: 对准总预算1 s、零角平均采样预算100 ms；TIM3逐阶段对准，ADC边界输出，完成后关闭驱动器/MOE并发布READY，保持`current_loop_enable=0`、`motor_ready=0`。初始化PID在采样前完成，首次ARM清动态状态；普通目标更新不清积分。收到合法禁能或Bus-off会中止自动启动

### 编码器失效两级保护

`AS5047P_EncoderCache_Read()` 在读取时刻计算角度年龄（阈值 2 ms）。电流环据此分级响应：

| 级别 | 条件 | 动作 |
|------|------|------|
| 0 | 正常 | 正常角度外推（上限 200 µs） |
| 1 | 数据陈旧，连续帧数 < 20 | **停止外推**（冻结在最后已知角度）+ 电流限幅折减至 30% |
| 2 | 数据陈旧，连续 ≥ 20 帧 (1 ms) | 置位`encoder_lost_latched`，锁存编码器故障并停止驱动 |

连续帧计数在角度年龄超过2 ms之后开始。另在DMA请求中每400次插入诊断读取，诊断响应不发布成角度；诊断缺少就绪位或磁场/运算状态异常会锁存故障。正常角度0仍合法。运行诊断间隔约20 ms，不能宣称对所有通信故障立即响应。

串口`[FAULT] reason=2`表示编码器故障。对应的`[ENC] cause=...`行提供最近诊断：`SPI`/`PARITY`/`EF`为通信错误，`LF_NOT_READY`为尚未就绪，`COF`为运算异常，`MAG_LOW`/`MAG_HIGH`为磁场异常，`MAG_ZERO`为幅值为零，`NO_DATA`为全1响应，`UNSTABLE`为未取得连续两组有效诊断。`dia`/`mag`保留完整16位响应，包含校验和EF位；`spi`为两个读取的HAL状态（0=OK、1=ERROR、2=BUSY、3=TIMEOUT），`err`斜杠后为ERRFL记录是否有效。运行期`mag`仍是启动读数；最近诊断正常也不能排除角度帧陈旧。

### 安全停机 `foc_safe_stop()`

`foc_safe_stop()`保留兼容签名，软件故障由`motor_fault_trip()`统一处理：

```
1. 锁存首次故障原因
2. DRV_EN = 0，清TIM1 MOE    → 先禁能，再清CCR；不依赖CCR预装载生效
3. 保存首次故障快照          → 主循环异步记录，ISR不格式化日志
4. 清目标、PID积分/历史输出与滤波状态
5. current_loop_enable、motor_ready、alignment_in_progress = 0
```

锁存后所有使能和PWM输出入口拒绝恢复。CPU异常入口与`Error_Handler`先调用最小寄存器关断，不调用完整控制器清理。复位后会重新校准和对准；IWDG及异常复位保持禁能策略尚未实施。

> ⚠️ **当前无自动恢复机制**：故障停机或 `Error_Handler` 触发后，需**复位 MCU** 才能重新使能。这是刻意选择——DRV8323H 的 OCP/OTW 等故障具有自恢复特性，自动重入闭环会在功率级瞬间施加积分器里积攒的满幅指令。

### 其他保护

- **对齐阶段过流**: `FOC_ALIGN_CURRENT_LIMIT_A = 1.0 A`，持续 3 ms 即中止对齐并关断
- **占空比限幅抗饱和**: 占空比被限幅时，通过 `foc_duty_to_dq()` 严格反算实际施加的 dq 电压并回灌给积分器
- **dq 电压矢量抗饱和**: SVM 线性区限幅后把实际施加量回算到 Id/Iq 积分器
- **ADC与相电流**: 未滤波三相电流保护在ADC回调入口执行，对准期间同样生效；检查可信码窗口、单帧严重过流及各相连续过流。TIM1监测ADC停更（2 ms预算），nFAULT运行期轮询
- **阈值状态**: CAN初始Iq限值1.5 A；指令/软/硬阈值为2.5/2.8/3.0 A。该设置未经电机、整板额定及实测噪声验证，不代表安全额定。软件保护不能覆盖所有短时尖峰、nFAULT短脉冲或ISR卡死。

## CAN 第二阶段 Iq 台架控制（2026-10-15）

`Core/Src/can.c`负责FDCAN传输、周期发送、有界请求/应答队列和恢复；`can_protocol.c`为无HAL依赖的协议编解码。保留`CAN_Init()`/`CAN_Poll()`主程序集成入口，ADC回调调用`CAN_OnCurrentSample()`记录实际采样进度。CubeMX生成的`fdcan.c/h`负责硬件，两个FDCAN IRQ进入HAL回调。旧`can_test.c/h`及0x124固定发送已删除。

| 项目 | 配置 |
|------|------|
| 引脚 | PA11 RX、PA12 TX，AF9 |
| 时钟 | PCLK1 170 MHz，FDCAN Divider=2，得到 85 MHz |
| Nominal Prescaler / SJW / Seg1 / Seg2 | 5 / 1 / 13 / 3 |
| 波特率 / 采样点 | 85 MHz ÷ 5 ÷ (1+13+3) = 1 Mbit/s；82.35% |
| 模式 | Classic CAN、Normal、自动重传开启、TX FIFO |
| 接收 | 3个精确标准过滤器：0x001广播及0x120+n目标→FIFO0，0x300+n请求→FIFO1；其他ID/扩展/RTR拒绝 |
| NVIC | FDCAN IT0/IT1=3，USART2/DMA3/4=4；ADC/TIM/SPI保留原值 |
| 线上格式 | 标准Classic数据帧，DLC严格8，BRS关闭，小端；协议版本0x00010100，固件版本由 `APP_FIRMWARE_VERSION` 提供 |
| 节点配置 | `motor_profile.c` 根据 `APP_MOTOR_PROFILE` 选择固定 profile；`APP_MOTOR_NODE_ID` 可为该镜像指定唯一节点号，0为未配置且停止节点帧/自动对准 |
| 心跳 | 0x700+n，每50 ms；状态、模式、故障16位、实际applied_seq、ADC进度、有效指令接收年龄（未运行255） |
| 管理 | 请求0x300+n，应答0x380+n；支持会话、Iq/ARM、参数子集、校准保活及可恢复通信故障清除；HOME仅停止路径 |
| 故障 | 0x080+n事件，心跳/查询仍可读取故障；故障事件优先于管理应答和心跳 |

第二阶段新增 `motor_supervisor.c`、`motor_alignment.c`、`motor_port.c` 和 `ina219_service.c`。TIM3 1 kHz处理有界管理请求、推进对准并监督租约；ADC 20 kHz在完整帧边界应用目标并发布1 kHz采样快照，CAN发送250 Hz快速反馈和5 Hz多圈位置。普通目标更新不重置PI；输出运行时实际已应用目标接收年龄达到20 ms关断，重复/非法目标不续期。保留自动上电偏置/电气校准，完成后关闭输出，不自动ARM。

当前裸电机默认 WHEEL profile，source=CAN，启动 mode=Iq；原有运行行为保持。JOINT profile 1 仅供诊断和采集模板，不含测得机械参数且运动资格关闭。profile 参数只读；`0x16` 改机械零点与 `0x17` 保存配置均返回 UNSUPPORTED；静止采样通过 GET_PARAM `0x0224` 只读获取。协议 1.1 的 JOINT 逻辑位置帧为 `0x200+n`，原始多圈位置仍用 `0x500+n`。默认限流与过流值仍是软件台架配置，不代表额定验收；真实 JOINT 运行尚未获资格或实物验证。

INA219使用I2C1 Event/Error中断（均优先级4），约5 Hz触发新转换并异步验证/读取，事务超时3 ms/转换预算8 ms；错误锁存、服务停用至复位，不阻塞CAN。主程序不再调用阻塞对准或阻塞I2C读。按用户要求暂不新增IWDG/nFAULT EXTI，现有nFAULT轮询保留；优先级0 ISR卡死未覆盖。完整测试帧、参数子集及上板步骤见[第二阶段台架记录](docs/can-stage2-bench-2026-10-15.md)。

单板试验将另一个活动CAN节点设为1 Mbit/s、正常模式（需ACK），观察节点1的0x701心跳。所有下表帧均为标准Classic、DLC=8，数据按十六进制显示：

| 目的 | 发送ID | 数据 | 预期 |
|---|---|---|---|
| 查询协议版本 | 0x301 | `01 01 00 00 00 00 00 00` | 0x381应答`01 01 00 00 00 00 01 00` |
| 查询当前状态 | 0x301 | `02 02 00 00 00 00 00 00` | 0x381应答，byte2=0；成功校准后value=`04 00 02 00`（READY/Iq/WHEEL/CAN），输出关闭 |
| 查询CAN错误 | 0x301 | `02 03 04 00 00 00 00 00` | value=TEC\|REC<<8\|BO<<16\|EP<<17 |
| 本节点禁能 | 0x301 | `12 04 00 00 00 00 00 00` | 输出关断，应答`12 04 00 00 00 00 00 00` |
| 全部节点禁能 | 0x001 | `00 00 00 00 00 00 00 00` | 输出关断，不应答 |

管理格式为opcode、request_id、selector/index两字节、argument四字节。缓存最近8项请求、有效2 s；重复相同请求返回缓存结果，同request_id不同内容返回CONFLICT（9），新的状态查询应推进request_id。停止请求不因缓存冲突拒绝。

在Keil Watch查看`canDebug`：active=1、initStage=6、nodeId=1表示服务启动。txQueuedCount仅为入队，txCompleteCount为HAL发送完成；rxCount记录合法格式帧，rxIgnoredCount包括拒绝目标；rxLostCount、requestQueueFullCount、tec/rec/busOff、halError定位错误。不增加接收LED或周期串口统计。周期心跳最多占一个硬件槽，TX满不等待、不积压历史心跳。

Bus-off中断立即关断并锁存通信故障；主循环取消旧TX，至少100 ms后清INIT请求恢复，等待真实BO解除及TX取消完成，最多尝试3次（本阶段每次启动总上限）。单次等待250 ms，不能仅凭清INIT宣称已恢复；重试耗尽保持禁能，需排查后复位。恢复通信不清故障/不恢复输出。机制依据[ST RM0440](https://www.st.com/resource/en/reference_manual/rm0440-stm32g4-series-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)，物理恢复仍需上板验证。

故障位图由监督模块统一保存：硬/软实测过流分别bit0/1，ADC越界bit2/3，校准bit4、驱动bit5、编码器bit6、非有限数bit7、控制停滞bit8、对准bit9、指令超时bit10、Bus-off bit11。旧母线监测故障仍报告bit15，RAM保留reason=11。停止不清故障；通信故障清除不会自动使能，硬故障需复位。

主机回归编译实际生产CAN/协议/FOC/监督/对准/I2C模块并模拟外设，覆盖profile=0/1两种配置、节点0/1/63、CAN关闭、会话序号、ADC使能、PI保持、租约、异步缓存、反馈及I2C错误。ARMCC5完整编译链接用于验证配置；这些不证明新HEX的实物保护时序或六节点已验收。第一阶段COM16/SLCAN已实际收到心跳与查询应答；2026-10-15用户烧录后，COM16只读验证新固件版本、READY/禁能、电气校准有效和零故障；接收窗口内反馈约249.4 Hz、心跳20 Hz、位置5 Hz，10个查询全部应答。随后禁能实物测试通过会话缓存/冲突/过期、参数边界、序号回绕、越界目标拒绝、停止撤销会话；757帧快速反馈输出关闭、故障及CAN错误计数为0，临时Iq限值已恢复200 mA。后续用户烧录并完成低电流短时复测：零目标ARM保持1 s、20 mA/250 ms与50/100 mA短脉冲反馈、显式禁能、断流通信超时和清除后保持禁能共25项断言通过，未再出现ADC停滞。50/100 mA稳态精度、物理关断时延和最坏执行时间仍待验收；详见docs/can-stage2-bench-2026-10-15.md。后续见[主方案](docs/can-wheel-leg-design-2026-10-02.md)和[实施规格](docs/ai-implementation-spec-2026-10-05.md)。docs/tests继续按.gitignore忽略。

| 文件 | 位置 | 内容 |
|------|------|------|
| `usart.c` | `USER CODE BEGIN 0` | `extern volatile uint8_t huart2_ready;` |
| `usart.c` | `USER CODE BEGIN USART2_Init 2` | `huart2_ready = 1U;` |

| `tim.c` | `USER CODE BEGIN 0` | `extern volatile uint8_t htim1_ready;` |
| `tim.c` | `USER CODE BEGIN TIM1_Init 2` | `htim1_ready = 1U;` |
| `fdcan.c` | `USER CODE BEGIN FDCAN1_Init 0 / 2` | `APP_CAN_ENABLE` 的条件编译开始与结束 |
| `main.c` | `USER CODE BEGIN Includes / 2 / WHILE` | `can.h`、`CAN_Init()` 和 `CAN_Poll()` 调用 |

**CubeMX 中的关键配置**（改动后将影响固件行为）：

| 外设 | 配置 | 原因 |
|------|------|------|
| USART2 | 波特率 **460800** | 14 通道遥测带宽需求 |
| TIM1 | 中心对齐1, ARR=2125, RCR=3, 死区=0 | 40 kHz 载波 / 20 kHz 触发；死区由 DRV8323H 内部生成 |
| ADC1/ADC2 | 双模式注入同步, 16× 过采样, 右移 4 | 与 `CURRENT_FACTOR` 定标配套 |
| PB9 (NFAULT) | 输入，无上下拉 | 外部已有 10 kΩ 上拉 |
| PB13/14/15 | 输出，上电置**高** | DRV8323H 3x 模式 INLx 需确定电平 |
| PB10 (DRV_EN) | 输出，上电置**低** | 保证上电时功率级关断 |

> ⚠️ **不要**将 PB13/PB14/PB15 的上电电平改为低——它们必须为高才能保证 3x 模式输入级不悬空。

**新增源文件时**: `uart_tx.c` 和 `can.c` 需保留在 Keil 工程的 `Application/User/Core` 分组（CubeMX 不管理非生成文件）；HAL 驱动组需包含 `stm32g4xx_hal_fdcan.c`。
